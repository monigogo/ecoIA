# BDNS / SNPSAP API validation

## Why this document exists

`BDNSService` (`app/services/bdns_service.py`) talks to the BDNS / SNPSAP
REST API to find candidate subsidies. The path
`/convocatorias/busqueda` was chosen as a tentative, mock-friendly
default. Before relying on BDNS in runtime we must confirm the real
endpoint and its parameters against the published OpenAPI document.

The official Swagger lives at:

```
https://www.infosubvenciones.es/bdnstrans/doc/swagger
```

It is also configurable via `BDNS_SWAGGER_URL` in `.env`.

## How to validate

We do NOT auto-update `BDNSService`. The expected workflow is:

1. Run the inspector in **offline mode** with the bundled fixture to
   confirm the script works:

   ```bash
   python scripts/inspect_bdns_swagger.py
   ```

2. Run the inspector in **online mode** when network access is
   available:

   ```bash
   python scripts/inspect_bdns_swagger.py --online
   ```

3. Open `docs/bdns_openapi_snapshot.md` and review the section
   "Candidate search endpoints (heuristic)". Pick the path that BDNS
   currently exposes for convocatoria search.

4. If the real path differs from `/convocatorias/busqueda`, update the
   constant `_CONVOCATORIAS_PATH` in `app/services/bdns_service.py` and
   add a regression test against the new fixture.

5. Commit both `bdns_openapi_snapshot.md` and the updated fixture
   (`tests/fixtures/bdns_swagger_sample.json`) so future drift is
   visible in version control.

## Fixture vs. live document

- `tests/fixtures/bdns_swagger_sample.json` is a curated subset used
  to keep tests hermetic and to give the inspector something to chew
  on offline.
- `docs/bdns_openapi_snapshot.md` is regenerated by the inspector. It
  is informational; do not edit by hand.

## Acceptance for runtime use

The BDNS integration is considered "runtime ready" only when:

- the real Swagger has been inspected at least once;
- the canonical convocatoria search path is recorded in this
  document (replace this section with the confirmed value);
- `BDNSService` uses that path verbatim;
- the integration test (`tests/integration/test_bdns_mock.py`) mocks
  the same path the service hits.

Until then `search_subsidies` should be treated as MVP-only and the
agent must keep declaring `requires_verification=True` on every
candidate.
